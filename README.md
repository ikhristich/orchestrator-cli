# Orchestrator CLI

**От описания задачи до проверенного результата — в одном терминальном интерфейсе.**

Orchestrator помогает работать над Git-проектами с помощью моделей из **Codex CLI и OpenCode**. Он организует работу аналитика, разработчика, тестировщика и ревьюеров: передаёт результаты между выбранными ролями, сохраняет замечания и решения, запускает независимые проверки и собирает результат для экспорта.

Откройте нужный проект через `cd`, выполните `orch` и опишите, что нужно сделать. Сценарий, модели, автономность и лимиты настраиваются внутри приложения короткими `/`-командами.

## Что умеет приложение

- **Подбирать процесс под задачу.** Только аналитика, разработка без отдельного этапа тестирования, работа по готовым требованиям или полный цикл с ревью.
- **Использовать разные CLI и модели.** Можно назначить один профиль всем ролям или отдельную модель каждой роли — из доступных в вашем Codex/OpenCode.
- **Показывать ход работы.** Лента доступных публичных сообщений и действий, текущая роль, индикатор работы, замечания, документы и diff. Состав промежуточных событий зависит от CLI.
- **Принимать корректировки.** Задачу можно остановить, уточнить направление и продолжить. В ручном режиме запуск роли и приёмка результата подтверждаются в диалоге.
- **Проверять код независимо от ответов модели.** Команды проверок выполняются в изолированной среде на macOS и Linux. Для успеха нужны корректный код выхода и заданная строка результата.
- **Сохранять историю и расход.** Настройки разделены по проектам; действуют лимиты токенов, попыток, ревью и времени. Повторная попытка не обнуляет расход. Телеметрия токенов может быть неполной — интерфейс показывает это явно.
- **Подключать собственные skills.** Дополнительные инструкции можно хранить в Markdown-файлах вне проекта и назначать выбранным ролям.
- **Экспортировать результат.** Документы, изменения кода, сведения о ревью и выполненных проверках сохраняются в отдельную папку.

## Как проходит работа

В полном сценарии процесс выглядит так:

1. **Аналитика:** уточняются требования, критерии приёмки и затрагиваемые части проекта; результат передаётся ревьюеру требований.
2. **Разработка:** готовятся изменения и техническое описание решения, выполняются независимые checks и ревью кода.
3. **Тестирование:** создаются тесты и план проверки по согласованным требованиям; результаты проходят checks и ревью тестов.
4. **Исправления и разбор разногласий:** замечания могут возвращать работу нужной роли; спорные решения и повторные проверки фиксируются в истории.
5. **Приёмка и экспорт:** пользователь просматривает результат и сохраняет готовые материалы.

Споры между ролями, решения и повторные попытки сохраняются в истории. Выполненная команда проверки и одобрение ревьюера отображаются отдельно.

Для работы используется зафиксированная версия Git-проекта и отдельные рабочие копии. **Результат не применяется к исходному проекту автоматически:** сначала его можно посмотреть в diff и артефактах, затем экспортировать.

| Что нужно сделать | Сценарий |
|---|---|
| Разобраться в задаче и подготовить требования | `/workflow analysis` |
| Реализовать фичу без отдельного этапа тестирования | `/workflow feature` |
| Разработать по готовой аналитике | `/workflow develop` и `/analysis FILE` |
| Разработать и протестировать по готовой аналитике | `/workflow develop-test` и `/analysis FILE` |
| Провести только тестирование | `/workflow test` |
| Пройти полный цикл | `/workflow full` |

Состав ревью настраивается отдельно. Отключение этапа тестирования не отменяет независимые проверки кода, заданные для разработки. Для сценариев без аналитического этапа требования можно передать файлом или в тексте задачи.

## Установка

### Windows

Запустите `.exe` двойным кликом. Приложение устанавливается для текущего пользователя, добавляет `orch` в PATH и создаёт запись удаления в настройках Windows. После установки откройте новое окно Windows Terminal или PowerShell:

```powershell
cd C:\path\to\project
orch
```

### macOS

```sh
sh ~/Downloads/orch-0.1.3-darwin-arm64.command
```

Для Intel Mac выберите файл `darwin-x64.command`. В новом терминале:

```sh
cd /path/to/project
orch
```

### Linux

```sh
sh ~/Downloads/orch-0.1.3-linux-x64.run
```

Для ARM64 выберите соответствующий файл. На Debian/Ubuntu установщик автоматически проверит Bubblewrap и при необходимости установит системные пакеты и штатный профиль AppArmor. Для этих действий `sudo` может запросить пароль. Глобальные ограничения безопасности не отключаются, существующие профили администратора не перезаписываются.

Если настройку прервали: `orch setup-sandbox`. Проверка без изменения системы: `orch doctor`.

## Первый запуск

Нужны Git и установленный авторизованный Codex CLI либо OpenCode. Их авторизация и проекты в установщики не входят. Node.js/npm для запуска приложения отдельно устанавливать не требуется.

1. Перейдите в Git-проект с хотя бы одним коммитом и выполните `orch`.
2. `/setup` — настройте проект; `/model all` — выберите CLI и модель.
3. Для разработки задайте границы кода и команду независимой проверки через `/pipeline`, затем выберите `/workflow`.
4. Опишите задачу обычным текстом. При ручной автономности подтверждайте роли в диалоге.
5. `/activity` — ход работы; `/pause` и `/steer уточнение` — остановка и корректировка.
6. `/read` — документы результата; `/export` — сохранить результат отдельно.

Для начала можно выбрать небольшой сценарий `/workflow analysis`, чтобы проверить подключение CLI и познакомиться с процессом без разработки кода.

Запуск интерфейса сам по себе не вызывает модель. История, настройки и бюджеты разделены по проектам. Экспорт не применяет изменения к исходному проекту автоматически.

## Команды для ежедневной работы

| Команда | Для чего |
|---|---|
| `/setup` | Настройки текущего проекта |
| `/model` / `/model all` | Выбор CLI и модели для роли / всех ролей |
| `/pipeline` | Границы кода и тестов, команда независимой проверки |
| `/mode manual` / `/mode checkpoints` / `/mode auto` | Режим автономности новых задач |
| `/activity` | Лента сообщений и действий |
| `/pause` / `/steer уточнение` / `/resume` | Остановка, корректировка и продолжение |
| `/findings` / `/checks` / `/diff` | Замечания, результаты проверок и изменения |
| `/read` / `/export` | Просмотр документов и экспорт |
| `/runs` / `/new` | История проекта и новая задача |
| `/skills add PATH` | Подключение папки с Markdown skills |
| `/help` | Список команд и горячих клавиш |

Между вкладками можно переключаться кликом или Control+T / Control+O. Лента прокручивается колесиком и тачпадом. Если прокрутить вверх, новые события не будут сбивать выбранное место; возврат вниз включает слежение за лентой.

## Поддержка платформ и текущие ограничения

- **macOS и Linux:** полный сценарий с независимыми checks. На Linux требуется работающий Bubblewrap; автоматическая установка пакетов и штатного профиля AppArmor поддерживается для Debian/Ubuntu и производных.
- **Нативные независимые checks Windows пока не реализованы.** Для полного сценария используйте Linux-версию внутри WSL2, с отдельной авторизацией CLI в Linux.
- Установщики пока не подписаны сертификатом издателя. ОС может показывать предупреждение о неизвестном приложении. Защиту ОС отключать не нужно.
- Windows EXE собраны и проверены распаковкой и контрольными суммами; нативный прогон Windows в этой версии локально не выполнялся.

## Обновление и удаление

`orch --version` показывает версию. Для обновления запустите новый установщик или используйте `orch update PATH`. Удаление — `orch uninstall` (на Windows также через настройки приложений). История и результаты сохраняются; активные или неподтверждённые задачи блокируют удаление.

Этот репозиторий предназначен для распространения установщиков и инструкций. Пользовательские проекты, локальные запуски и учётные данные не публикуются.
